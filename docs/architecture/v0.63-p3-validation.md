# v0.63 P3 — retained guarded Core API

V0.63 retains the existing guarded Core API for worker activation runtime
interface prerequisite evidence. The exact surface remains an owner-scoped
candidate-record collection `POST`/`GET` and item `GET`; it adds no successor
schema, route, permission, consumer, or operational authority.

The service factory is explicitly fail-closed. Omitting its feature flag keeps
the service disabled, and a disabled request returns the redacted unsupported
capability response before reading the retained predecessor evidence or
changing the bounded journal. Production startup does not construct this
service.

The retained route continues to require authenticated operator permissions,
trusted Origin/CSRF on `POST`, a bounded visible-ASCII `Idempotency-Key`, strict
JSON/framing, owner/candidate binding, no-store responses, and redacted
dependency failures. No Agent, worker, runtime, execution, installation,
dispatch, retry, or resend consumer is added.

## Validation

`test_v063_guarded_api.py` proves the omitted factory flag is default-off and
that the refusal is side-effect-free. Existing retained route coverage proves
the exact methods, authentication, CSRF/origin, bounds, ownership, OpenAPI,
response validation, and redacted-failure behavior.
