# v0.59 P2 — retained durable evidence boundary

The [v0.59 freeze](v0.59-runtime-interface-boundary.md) and integrated P1 retain
v0.57 evidence with v0.58 hardening. This change implements additional bounded
storage and owner-scoped read enforcement in that existing service. It does not
invent a v0.58 prerequisite pair or a v0.59 successor journal. The exact durable
predecessor remains v0.56 review/status, including the stable status at review
`recorded_at` and independent trusted-time eligibility at both write locks.

The journal now checks the SQLite storage class and byte bound of every selected
cell, including denormalized reservation indexes and terminal subject indexes,
before fetching rows into Python. Previously only JSON cells had this preflight;
a corrupt index could materialize a value approaching the database page ceiling.
Every valid indexed value is contained in its bounded evidence envelope, so the
existing model bound also bounds each index without excluding valid evidence.
Corruption remains terminal and redacted; no repair, deletion or eviction occurs.

Service item reads validate canonical candidate and prerequisite IDs before
accessing storage, strictly reparse returned evidence, and independently check
its exact owner/candidate/prerequisite ID before returning a status. A valid
record returned for another scope receives the same redacted not-found result
as missing evidence. Existing valid read responses are unchanged.

Permanent owner/key and subject reservations, exact duplicate readback without
predecessor reads or freshness renewal, ambiguous append closure, restart
retention, bounded capacity and SQLite write-lock ordering remain intact. The
schema, application ID, domains, vectors and consumer inventory are unchanged.
Creation remains explicitly constructed and default-off. Agent, worker and
execution gain no effects or authority.
