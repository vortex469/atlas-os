## Decision and phase authorization

The P0 verdict is reconciled and retained: the repository does not establish a
trusted author, a distinct control-plane activation decision, authenticated
effect-plane contact, or one-shot uncertainty recovery. Therefore **P1–P5 are
deferred**, rather than authorized as reference-only evidence phases. The only
permitted follow-up is documentation or validation that cannot add a schema,
marker, route, permission, consumer, runtime client, credential, migration,
or behavior.

The P0 analysis is evidence for this decision, not a provisional successor
contract. In particular, the v0.64 runtime-definition status cannot be
promoted into activation authorization by renaming, wrapping, or re-reading
it.

## Explicit exclusions

Nothing in this Sync authorizes queue claim/lease/ack/consume/requeue, store or
runtime contact, activation, admission, worker start, Agent invocation,
execution, installation, deployment, rollback, publication, retry/resend,
repair, replay, or runtime enablement. It adds no successor UUID/hash domain,
schema, ID, route, permission, credential, migration, process, container,
effect-plane consumer, or API/UI action. Mission Control remains GET-only and
read-only.

## Acceptance evidence and stop conditions

This boundary is accepted only as a planning freeze when all of the following
are recorded: the predecessor/P0 pins above, source-link checks, focused
retained-contract regressions, `git diff --check`, and a hostile review that
finds no authority promotion. These checks do not constitute release
acceptance.

Any future reopening must first provide a separate normative decision with an
exact owned subject and predecessor fingerprint, trusted author and approval
provenance, a distinct consumer decision, authenticated effect-plane peer,
immutable measurable limits, durable reservation-before-effect, idempotent
one-shot recovery, and proof of zero unauthorized consumers. Stop immediately
if any proof is missing, if a fixed-false field changes, if GET-only UI becomes
actionable, if provenance is ambiguous, or if a focused test is treated as
release acceptance. Do not invent a successor schema to fill an unmet gate.

No release, tag, push, deployment, enablement, or operational authority
follows from this Sync.
