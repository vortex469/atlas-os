# Selected sequential implementation: v0.71–v0.80

The operator requested local commits and continued implementation through
v0.80, following the completed v0.70 work. Each version requires its own
behavior change, focused tests and completion record. These are local,
unreleased implementation milestones; no push, tag, publication, deployment,
production runtime/backend enablement or installation capability is authorized.
Exact approvals for real model/verification/commit execution requests remain
separate. No new account credential use is assumed.

The last three scopes follow inspected gaps in `workspace.py` (unbounded Git
and partial-clone failure), `runner.py` (changed workspace HEAD) and its
hard-coded attestation. Inspect the existing contracts before changing them;
where a boundary already rejects a case, preserve it and close the earlier
worker-side gap rather than adding a competing authority.

The seven installation blockers, 67 fixed-false fields and deferred successor
control plane remain unchanged. Local acceptance is not release or production
acceptance. Preserve the known nested patch-helper limitation and all existing
approval/no-replay boundaries. Run integrated affected suites and existing
container/recovery gates at a clean committed implementation before closeout.

## v0.71 acceptance

A 2 MiB inbound budget is enforced for declared and streamed bodies before JSON
parsing or ledger claim. Invalid, duplicate, mismatched or ambiguous framing is
refused. Overflow returns controlled HTTP 413 `request_too_large`; malformed
lengths return 400. Existing peer/authentication checks still happen first.
Tests cover declared overflow, streaming without Content-Length and mismatched
length; the ledger stays empty. Fourteen focused worker tests pass. No real
model, credentials, execution enablement or production changes are involved.

## v0.72 acceptance

Git status is parsed as NUL-delimited bytes with recursive untracked paths.
Rename/copy records retain both endpoints, so a rename cannot erase an
out-of-scope source. UTF-8 spaces, newlines, arrows and non-ASCII names preserve
exact identity; unsupported encodings/paths fail closed without patch output.
Nineteen workspace tests pass, including a newline-named out-of-scope edit.

## v0.73 acceptance

Patch generation now uses the bounded process reader and a 30-second Git
budget. The existing text contract limits complete transported patches to
1 MiB (without expanding the separate 4 MiB digest/size ceiling). Any truncated
or invalid-UTF-8 patch produces additive `patch_too_large`, with no retained
patch, prefix digest or changed-file approval. Older agents that do not know
the code remain unknown rather than applying data. Out-of-scope changes stop
before diff capture. A 2 MiB fake edit is discarded and its clone removed.
Sixty-five workspace/backend tests pass, including the new failure mapping.

## v0.74 acceptance

Before publishing a private diagnostic copy, the exporter now checks the exact
ledger table schema, version, single-attempt state, request identity/digest,
terminal result contract and state/result consistency. Domain validation is
read-only and grants no authority; the recorded request digest is not an
independently recomputed approval. Nine tests cover complete private copies,
truncation/corruption, no overwrite, unrelated schema, invalid states/digests,
missing terminal results and mismatched result identity. Originals remain
unchanged and invalid copies are not published.

## v0.75 acceptance

The maintained nested sandbox probe now emits independent shell-boundary and
helper-network-namespace observations. Its helper check is a bounded,
credential-free Bubblewrap process, never a model invocation. Raw helper output
is excluded. Supported/unavailable primitive results cannot assert full runtime
readiness or activation authority. Four tests cover success, failure, missing
helper and timeout. The final isolated runsc rehearsal will record the actual
helper outcome without weakening isolation or claiming all CLI helpers work.

## v0.76 acceptance

The existing workflow GET projection now includes per-stream retained/observed
byte counts and truncation flags, without raw model output. Mission Control
shows a shortening notice and preserves separate verification/commit approval
controls. The additive field is optional for older UI/Agent combinations.
Thirteen focused Agent and 39 page tests pass; tests assert projection and
rendering cause no worker submission, lookup or approval decision.

## v0.77 acceptance

`scripts/atlas-repository-action-check` is a maintained, credential-free native
fixture checker with fixed approval/journey/recovery/audit phases. It reuses
the existing immutable request, separate approval, lost-response/restart and
terminal audit fixtures, rather than adding a competing workflow authority.
All 72 selected fixture checks pass. Seven tool/guard tests cover explicit
phase selection, private output refusal/retention and non-loopback connection
and DNS refusal. Real Codex is blocked on PATH; credentials/configuration are
not inherited into the fixture environment. Approvals are explicitly synthetic
test data, never operator approvals or production effects. The tool is a local
check runner, not a general command executor or a new evidence stage.

## v0.78 acceptance

Workspace source inspection, clone and cloned-HEAD validation share a setup
budget of min(30 seconds, requested command timeout). Clone failures/timeouts
remove partial owned directories and never invoke a model. Git staging, status
and metadata also use bounded process-group readers with fixed 30-second
helper limits; unsupported/truncated metadata fails closed. Source-specific
Git trust and no-local/no-hardlinks remain intact. Twenty-eight workspace and
process tests pass, including failed and timed-out partial clones. The setup
and helper budgets are explicit, not a claim of one combined model/setup
deadline. Sources stay unchanged and no replay or activation is introduced.

## v0.79 acceptance

Before post-model Git, bounded fingerprints check HEAD/ref/config and critical
repository control files. Revision/config changes, replacement refs, unsafe
symlinks or unreadable metadata fail as `stale_repository`, with no patch. Git
collection disables hooks, filesystem monitors, text conversion and replacement
objects. Twenty-six workspace tests pass, including model-created commits,
malicious config, replacement refs and a hook that must never run. This is a
worker-side refusal boundary, not commit authority. The existing process-session
escape qualification and outer sandbox requirement remain explicit.
