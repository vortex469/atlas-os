The operator requested local commits and continued implementation through
v0.80, following the completed v0.70 work. Each version requires its own
behavior change, focused tests and completion record. These are local,
unreleased implementation milestones; no push, tag, publication, deployment,
production runtime/backend enablement or installation capability is authorized.
Exact approvals for real model/verification/commit execution requests remain
separate. No new account credential use is assumed.

## v0.71 acceptance

A 2 MiB inbound budget is enforced for declared and streamed bodies before JSON
parsing or ledger claim. Invalid, duplicate, mismatched or ambiguous framing is
refused. Overflow returns controlled HTTP 413 `request_too_large`; malformed
lengths return 400. Existing peer/authentication checks still happen first.
Tests cover declared overflow, streaming without Content-Length and mismatched
length; the ledger stays empty. Fourteen focused worker tests pass. No real
model, credentials, execution enablement or production changes are involved.

## v0.72 acceptance

Git status is parsed as NUL-delimited bytes with recursive untracked paths.
Rename/copy records retain both endpoints, so a rename cannot erase an
out-of-scope source. UTF-8 spaces, newlines, arrows and non-ASCII names preserve
exact identity; unsupported encodings/paths fail closed without patch output.
Nineteen workspace tests pass, including a newline-named out-of-scope edit.

## v0.73 acceptance

Patch generation now uses the bounded process reader and a 30-second Git
budget. The existing text contract limits complete transported patches to
1 MiB (without expanding the separate 4 MiB digest/size ceiling). Any truncated
or invalid-UTF-8 patch produces additive `patch_too_large`, with no retained
patch, prefix digest or changed-file approval. Older agents that do not know
the code remain unknown rather than applying data. Out-of-scope changes stop
before diff capture. A 2 MiB fake edit is discarded and its clone removed.
Sixty-five workspace/backend tests pass, including the new failure mapping.

## v0.74 acceptance

Before publishing a private diagnostic copy, the exporter now checks the exact
ledger table schema, version, single-attempt state, request identity/digest,
terminal result contract and state/result consistency. Domain validation is
read-only and grants no authority; the recorded request digest is not an
independently recomputed approval. Nine tests cover complete private copies,
truncation/corruption, no overwrite, unrelated schema, invalid states/digests,
missing terminal results and mismatched result identity. Originals remain
unchanged and invalid copies are not published.
