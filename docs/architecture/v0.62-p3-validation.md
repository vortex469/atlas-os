# v0.62 P3 — retained guarded Core API

V0.62 retains the existing guarded Core API for worker activation runtime
interface prerequisite evidence. The exact surface remains an owner-scoped
collection `POST`/`GET` and item `GET`; it adds no successor schema, route,
permission, consumer, or operational authority.

The service factory is explicitly fail-closed: omitting its feature flag sets
`enabled=False`. Production startup still does not construct this service, and
an explicitly constructed disabled service returns the redacted unsupported
capability response without reading or changing the predecessor journal.

The retained route continues to require authenticated operator permissions,
trusted Origin/CSRF on POST, a bounded visible ASCII Idempotency-Key, strict
JSON/framing, owner/candidate binding, no-store responses, and redacted
dependency failures. No Agent, worker, runtime, execution, installation,
dispatch, retry, or resend consumer is added.

## Validation

Focused validation uses the selected interpreter from the managed worktree with
`PYTHONPATH=services/atlas-core` and the route and retained service tests. The
factory regression proves omitted construction is default-off; existing route
coverage proves the exact methods, guards, bounds, response validation, and
production non-construction.
