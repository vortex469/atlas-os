# v0.61 P3 — retained guarded Core API

The [normative v0.61 boundary](v0.61-authority-boundary.md) retains the existing
v0.57 prerequisite POST/list GET/item GET API. That default-off implementation
already exists. This change hardens its POST failure boundary; successor API
implementation remains deferred, and no route, permission, schema, consumer or
production service construction is added.

Previously, an unexpected HTTP exception from the create dependency could be
classified as a request framing or validation failure (413/415/422), or missing
evidence (404). The create call now has a separate exception boundary returning
bounded, redacted, no-store, non-retryable 503 errors. Structured service error
models retain their validated domain mappings, including missing/foreign 404
and disabled creation 409. Authentication, request parsing and response binding
retain their existing behavior. No retry is attempted after dependency failure.

The expanded POST regression injects HTTP 200, 302, 401, 403, 404, 413, 415,
422, 429 and 503 exceptions. It checks authentication and malformed-body refusal
before dependency access; exact payload, owner, candidate, permission and key
arguments; bounded redaction and suppressed dependency headers; and no predecessor
reads or journal changes from the failing stub. Existing route tests cover
default-off behavior, missing services, strict framing, dedicated permissions,
CSRF, recursive lineage, response binding, idempotency, restart, corruption and
the exact registered API surface.
