## Core ownership-transition diagnosis and rerun

The failing assertion is intentionally unchanged in
`services/atlas-core/app/discovery/test_dynamic_cache.py`: as root it changes a
temporary cache root to UID/GID `12345:12345`, requires initialization to fail
closed, and verifies that the foreign ownership remains. The Workbench cannot
perform that transition. On 2026-09-29, `id` reported `uid=0(root) gid=0(root)`;
`/proc/self/uid_map` and `/proc/self/gid_map` each contained only `0 0 1`,
`/proc/self/setgroups` was `deny`, and `/proc/self/status` reported no
effective capabilities. A direct `/opt/atlas/.venv/bin/python` `os.chown`
probe returned `OSError: [Errno 22] Invalid argument` and the path remained
owned by `0:0`. The focused command therefore returned exit 1 for the host
limitation, not for a weakened or changed security assertion.

The focused assertion command was:

`PYTHONPATH="$PWD:$PWD/services/atlas-core" /opt/atlas/.venv/bin/python -m pytest -q services/atlas-core/app/discovery/test_dynamic_cache.py::test_non_owned_existing_root_fails_closed`

`timeout 900s env PYTHONPATH="$PWD:$PWD/services/atlas-core" PATH=/opt/atlas/.venv/bin:$PATH /opt/atlas/.venv/bin/python -m pytest -q services/atlas-core`
