# v0.59 P3 — owner-scoped API cache isolation

The synchronized [v0.59 freeze](v0.59-runtime-interface-boundary.md) already
retains the authenticated v0.57 prerequisite POST, collection GET and item GET.
The prerequisite P2 implementation is present at baseline `b7e8f847`.
This change adds `Cache-Control: no-store` to all successful responses and
redacted failures produced by those handlers. Cookie-authenticated evidence and
owner-specific missing/expired/unavailable outcomes must not be retained by
HTTP caches across sessions or reused in place of a fresh eligibility read.
The header instructs compliant caches; it does not purge previously stored data.

Success headers use FastAPI's injected response; errors set the header on their
explicit JSON response. The response bodies, status codes, strict schemas,
canonical fingerprints, exact lineage, permanent idempotency reservations,
response bounds and dedicated permissions retain their frozen behavior.
Creation remains default-off and requires explicit service construction.
No route, production consumer or downstream authority is added.
