# v0.59 P3 — retained guarded Core API

The [v0.59 freeze](v0.59-runtime-interface-boundary.md) retains the existing
authenticated prerequisite POST, collection GET and item GET. No successor
schema or route is selected. This change closes the retained GET framing guard:
both reads reject duplicate, malformed, oversized or nonzero Content-Length
and any Transfer-Encoding before accessing the evidence service. Received body
bytes remain forbidden even when Content-Length claims zero. Authentication
still precedes this check; ordinary empty GETs, including a single zero length,
retain their existing behavior. Rejections use the existing bounded, redacted,
non-retryable 422 envelope.

The v0.57 schemas, permissions and exact v0.56 lineage remain authoritative.
Creation still requires explicit service construction and is default-off.
The retained POST requires trusted Origin/CSRF, bounded strict JSON and one
bounded idempotency key; duplicate readback cannot renew evidence or replay
predecessor access. Response reparsing, owner/candidate/item/create-pin checks,
192 KiB envelopes and the sixteen-record collection ceiling remain intact.
All downstream fixed-false authority and the exact production consumer set
remain unchanged.
