# v0.68 — bounded worker command output

Status: implementation complete locally; unreleased. Depends on v0.67.

The worker drains stdout and stderr concurrently with selectors and retains
at most 1 MiB per stream, plus fixed-size read buffers. Output beyond the
retained prefixes is drained and counted rather than buffered in memory.
Results use the existing `BoundedOutput` contract, including retained text,
truncation and observed original byte counts. Invalid or incomplete UTF-8 is
discarded and reported as truncation instead of expanding replacement text
past the byte limit. The wire schema and approval/request hashes do not change.

The same process-group cleanup and deadline apply to chatty commands. Timeout
captures remain bounded, no patch is collected, and escaped-session output is
not allowed to prolong the read beyond the bounded cleanup grace. Timeout byte
counts describe drained bytes, not hypothetical later output.

Acceptance: all 62 worker tests passed. New cases drain simultaneous 4 MiB
stdout and stderr with 64 KiB retained per stream and less than 1 MiB of traced
capture allocations, validate partial/invalid UTF-8 against the existing
contract, and time out a continuously writing command without deadlock. The
v0.67 child-lifetime and timeout/no-patch cases continue to pass. Tests use
local fake commands, no real model and no account credentials.

This milestone bounds model-command output capture. Git patch generation is
a separate future scope; this does not claim that every subprocess or patch
allocation is bounded. Production activation and publication remain excluded.
