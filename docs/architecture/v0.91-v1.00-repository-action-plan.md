# Selected local repository-action continuation: v0.91–v1.00

The operator selected continuation through v1.00. This closes the selected
local repository-edit capability; it does not declare Atlas production-ready
or discharge the separate installation capability. No deployment, enablement,
account credentials, real model calls, push, tags or publication are selected.
Exact native implementation/verification/commit approvals remain separate.

Inspection found these concrete missing contracts. Implement each in order,
with focused regression coverage and scoped local commits:

## Implementation acceptance

v0.91: eight independent ledger contenders produce exactly one execution-start
winner. An API caller losing the start barrier returns the stored in-flight
state without invoking a runner. Existing HTTP response semantics stay stable.

v0.92: successful result persistence requires executing state. Candidate rows
are validated before update; invalid pre-start unknown/success results leave
state unchanged. Existing execution-disabled refusal remains supported.

v0.93: recovery validates every row and classifies interrupted executions in
one write transaction. A trigger-injected second-update failure rolls back the
first; a later retry classifies both once without executing anything.

v0.94–v0.95: SQLite claim/lookup/start/persistence failures produce controlled
503 responses without raw database details. Failed persistence after a run
leaves the request in-flight; duplicates do not rerun. Parser failures return
controlled 400 responses without caller data in responses or logs.

v0.96–v0.97: tokens follow the request contract and reserve quarantine. Git
safe-directory values round-trip quoted/backslash/comment-like paths exactly;
control characters are refused before writing config. Source checks use owned
process groups, ten-second/4-KiB bounds, sanitized failures and isolated Git
environment. Repository mapping size/count are bounded.

v0.98–v0.99: relay connect deadline is five seconds and total lifetime is
3,900 seconds, covering the existing 3,600-second execution maximum plus setup
and collection allowance. Neither deadline retries upstream work. Failure,
timeout and cancellation cancel/join both copy tasks and close owned streams;
close waits are limited to one second. TCP half-close preserves pending replies.

v1.00: health validates durable rows, exposes all five states, and reports 503
unavailable with null counts on corruption or database failure. It does not
classify or execute requests. Full readiness and activation authority remain
false. The container checker accepts additive state counts and legacy healthy
contracts while rejecting unavailable/incomplete new state contracts. All 175
worker tests and affected lint pass. Integrated final-source checks are pending.
