## v0.81 acceptance

Process budgets must be numeric (not bool), finite and positive, at most the
existing worker maximum of 3,600 seconds. Validation precedes Popen and handles
huge integers without numeric overflow. Fourteen process tests pass; invalid
budgets record zero launches. Existing output bounds and cleanup are unchanged.

## v0.82 acceptance

Submission and lookup share one constant-time ASCII-byte authentication check.
Missing, duplicated and non-ASCII headers return controlled 401 without a
claim; peer checks still happen first. Invalid/empty/oversized configured
credentials fail startup without echoing their values. Twenty worker tests pass.

## v0.83 acceptance

Both protocol peers and request JSON helpers use one strict UTF-8 object
decoder. Duplicate keys/nonfinite constants and non-object roots are refused.
Numeric schemas/counts/return codes reject bool/float aliases where integers
are required; time/duration reject boolean or non-representable values without
overflow. Valid integer/float representations and request hashes are preserved,
not normalized. All 101 focused protocol/transport/API tests pass.

## v0.84 acceptance

A five-second monotonic read/decode budget supplements the 2 MiB request cap.
Slow asynchronous streams are cancelled and synchronous decoding must finish
before the deadline to reach claim. Controlled 408 `request_timeout` carries
no request content. Twenty-seven focused API tests pass, including streams
and decoders that exceed their budget while the ledger stays empty.

## v0.85 acceptance

Prepare/disposal entry points validate the bounded request identifier and the
canonical owned root/path. The internal quarantine namespace is reserved.
Traversal, workspace symlinks and external quarantine roots are refused before
filesystem mutation; failed cleanup retains active ownership metadata. Valid
quarantine preserves its archive across later cleanup. Forty workspace tests
pass. This does not claim protection against deliberate session-escape races;
outer isolation and the existing ownership boundary remain required.

## v0.86 acceptance

An active workspace now records and compares the immutable request digest in
addition to HEAD. Changed argv/plan/scope/time representations cannot inherit
prior workspace material. Missing or mismatched active directories fail closed;
an exact unchanged request remains reusable within its active ownership. All
42 workspace tests pass. Durable execution idempotence remains ledger-owned.

## v0.87 acceptance

One pure contract now validates live and exported ledger fields, timestamps,
version, single-attempt state, start markers, strict result JSON and row/result
identity/state links. Live claims, transitions and lookups refuse corrupt rows;
startup validates all rows before classifying any executing attempt. Unsupported
schemas fail without migration. Twenty-seven ledger/export tests pass, including
invalid version/state/attempt/digest/time and no startup partial repair or replay.
The database is never automatically repaired and hashes do not grant authority.

## v0.88 acceptance

When patch payload bytes are present, size, digest and truncation evidence
must agree. Complete patches are hashed as UTF-8 bytes; truncated success is
refused, while correctly linked failed-result diagnostic prefixes remain
non-applicable. Legacy payload-absent metadata stays non-committable and is not
upgraded into authority. All 109 focused contract/backend/patch tests pass;
invalid payloads remain unknown without patch use, replay or local fallback.

## v0.89 acceptance

Health now separates configured execution from a pure, uncached isolation
observation. Disabled/unobserved/unsafe cases remain distinct. Neither safe
isolation nor service health asserts full readiness or activation authority.
GET creates no workspace, ledger claim or cached execution observation. The
container checker uses the bounded one-shot client and refuses configured
execution without safe observed isolation; legacy disabled health remains
compatible. Fifty-five focused API/isolation/health tests pass. No credentials
or real approvals are queried and no runtime setting is changed.

## v0.90 acceptance

The existing fixture checker now hashes its bounded relevant source set before
and after its fixed phases, records code content/commit/cleanliness and a log
digest, and atomically writes private reports. Changes during execution,
timeout, interruption or launch failure cannot become a complete pass. Pytest
runs in an owned process group that is stopped before report publication.
`--verify-report` is read-only and refuses stale source, modified logs, incomplete
results or scope mismatches. Eighteen checker/source tests and all 72 guarded
native fixture checks pass, including mid-run drift and partial-run refusal.
The real report also passed read-only verification.

The content hash identifies tested code, not a signature, environment identity,
operator approval, remote CI or release permission. A documentation-only commit
can change HEAD without invalidating matching code content; the original
commit/cleanliness remain historical metadata. The checker still accepts only
fixed synthetic phases, blocks real Codex and has no production authority.
This extends the existing check tool rather than introducing an evidence stage.
