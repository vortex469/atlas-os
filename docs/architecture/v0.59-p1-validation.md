## Implementation

Plain-tree reparsing previously checked depth but could expand a small graph of
shared references exponentially before checking the serialized envelope size.
The reparser now counts expanded values before allocating the complete tree.
Each value requires at least one JSON byte, so the existing 192 KiB ceiling is
a conservative upper bound on the count. The full canonical byte check still
applies afterwards. This adds no smaller wire limit and changes no valid
canonical bytes, fingerprints, immutable lineage or refusal vocabulary.

Hostile regressions cover dictionary, list and tuple graphs with over four
billion expanded values, using iteration counts to verify early termination.
Raw and constructed evaluator inputs produce identical redacted refusals.
Positive controls retain shared references within the size bound and verify
byte-exact canonical output without input mutation. Additional regressions
reject the deferred definition-review marker, including `false`, in validation
input, create, authority and both predecessor envelopes, including model-copy
bypasses passed to the record builder.

The evaluator continues to consume injected reservation facts; durable replay
enforcement remains the existing store's responsibility. No persistence, API,
UI, runtime effect, consumer allowance or release-gate change is included.

## Follow-up: bound repeated string contents

The retained reparser now also charges string contents and object keys against
its pre-allocation budget. Counting only values allowed shared large strings
or keys to produce oversized serialized output before the canonical byte check.
Character counts are conservative lower bounds on UTF-8 JSON bytes, so this
preserves every valid envelope within the frozen ceiling. Non-string object
keys are rejected during traversal, before copying their values.

New hostile regressions bound traversal of repeated large strings and keys,
check identical redacted evaluator refusals for raw and constructed inputs,
and verify unchanged source references. Positive controls exercise exact byte
ceilings with ASCII, multibyte UTF-8 and JSON escape sequences. Existing schema,
