# v0.58 P2 reconciliation and retained journal hardening

The [synchronized contract](v0.58-runtime-interface-admission-provisional.md)
and [P1 reconciliation](v0.58-p1-validation.md) retain the integrated v0.57
interface-prerequisite boundary and defer admission P1-P5 under A2. This change
hardens that existing bounded durable service/store. It introduces no successor
schema, v0.57-consuming reader, store, API, permission or evidence marker.

The retained store now resolves its journal path once at construction and opens
subsequent connections with SQLite `mode=rw`. Previously, changing the working
directory or retargeting a symlink could redirect later connections; reopening a
missing database could create an empty file before integrity validation refused
it. A live missing journal now returns the closed `unavailable` error without
creating any replacement or consulting the predecessor. Path-resolution errors
are redacted, and URI quoting keeps special filenames from overriding SQLite
connection modes. Explicit construction can initialize a new path; this does not
provide recovery from external deletion or substitution of durable history.

The application-ID-57 schema, immutable evidence and terminal audits, permanent
subject/key reservations, capacity ceilings, full lineage, two-lock revalidation,
owner-scoped v0.56 reader and default-off service remain the selected contract.
No retention eviction, retry, repair or runtime/Agent/worker/execution consumer
is added. New regressions cover missing live storage across create/get/list,
byte-exact retained history and restart replay refusal, working-directory and
symlink changes, URI metacharacters, and redacted symlink-resolution failure.
