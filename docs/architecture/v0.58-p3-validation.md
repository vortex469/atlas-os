# v0.58 P3 reconciliation and retained API hardening

The [frozen contract](v0.58-runtime-interface-admission-provisional.md) retains
the integrated v0.57 authenticated, owner-scoped evidence create/list/get API.
Admission P1-P5 remain deferred under A2. This task hardens that approved API;
it introduces no successor route, permission, schema, service construction or
downstream authority. Creation remains default-off.

POST now rejects a declared Content-Length that differs from the streamed body
length, simultaneous Content-Length and Transfer-Encoding, duplicate transfer
headers, and transfer encodings other than a single `chunked` value. These
requests receive redacted, non-retryable 422 errors before evidence access or
durable reservation. Existing malformed/oversized length rejection remains 413.
The 16 KiB streaming bound applies regardless of the declared framing. These
checks concern headers and decoded bytes delivered by ASGI; they do not replace
the HTTP server's wire-protocol framing validation.

Six rejection regressions assert zero predecessor reads and zero evidence,
reservation and audit writes. A streaming success regression covers chunked
create, exact duplicate through a subsequent length-framed request, no duplicate
predecessor read, and oversized streaming refusal. The existing API suite covers
authentication, dedicated permissions, CSRF, owner/candidate isolation, strict
schemas, exact lineage and key pins, bounded/redacted responses, fixed-false
authority, default-off construction, durable restart and replay refusal.
