# v0.69 — bounded worker response reads

Status: implementation complete locally; unreleased. Depends on v0.68.

The Agent's one-shot TCP worker client now caps response headers at 16 KiB and
response bodies at 24 MiB. It accumulates bytes with a bytearray rather than
repeated immutable concatenation and refuses overflow as `WorkerTransportError`.
Existing backend behavior preserves an unknown outcome without applying a patch,
retrying execution or falling back locally. The socket closes on refusal.

The body allowance covers three 1 MiB contract text fields even when JSON
escaping expands every byte sixfold, with metadata headroom. This is a transport
budget; it does not expand any result or patch authority or contract limit.

Acceptance: 59 focused Agent transport/backend/reconciliation tests passed.
Tests reject header and body overflow on one connection, assert no retries,
and accept maximum escaped stdout/stderr/patch text. Existing original-result
recovery, request binding and separate approval tests remain passing. All tests
are local and credential-free. Strict framing and a total deadline are the
separate v0.70 milestone, not claims made by this size-bound change.
