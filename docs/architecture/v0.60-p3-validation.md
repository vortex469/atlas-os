# v0.60 P3 — retained guarded Core API hardening

The [synchronized boundary](v0.60-runtime-definition-boundary.md) retains the
v0.57 prerequisite create/list/item API integrated through v0.59. The
[P2 implementation](v0.60-p2-validation.md) hardens that retained journal;
it supplies no successor evidence pair. P3 therefore hardens the existing
route rather than introducing a runtime-definition schema, endpoint or consumer.

Authenticated list and item GET previously shared an exception handler between
the permission guard and evidence access. An unexpected dependency HTTP exception
could consequently be misclassified as an authentication or throttle failure.
Each read now handles authentication separately: unexpected HTTP exceptions from
evidence access return a bounded, redacted, non-retryable 503. Missing/foreign
readback still returns 404, and actual authentication failures retain their
existing status mapping. Exception detail and headers are never forwarded.
Structured, strictly validated service errors retain their frozen mapping.

New regressions inject HTTP 200, 302, 401, 403, 404, 422, 429 and 503 failures
into both authenticated read paths. They check authentication precedes dependency
access, exact owner/candidate arguments, no-store bounded redaction, no forwarded
redirect/authentication/retry headers, no predecessor access and no journal
reservations or writes. The full retained API suite covers strict framing and
schemas, permissions/CSRF, exact lineage and idempotency pins, permanent
reservation, restart/expiry duplicates, foreign readback, bounded envelopes and
fixed-false authority. The release-closure suite checks durable lineage,
no-replay and the exact production consumer set.

Creation remains default-off with no production service construction. The three
frozen evidence operations and their schemas are unchanged. This change grants
no Agent invocation, worker start, execution, installation, deployment, rollback,
publication, retry/resend, polling or other downstream authority.

## Validation command and regression proof

Run from the managed worktree with the selected interpreter:

```sh
PYTHONPATH=services/atlas-core /opt/atlas/.venv/bin/python -m pytest -xq \
  services/atlas-core/app/routes/test_worker_activation_runtime_interface_prerequisite.py \
  services/atlas-core/app/worker_activation_runtime_interface_prerequisite/test_release_closure.py \
  --basetemp=.task-evidence/v060-p3/pytest-tmp --tb=short --disable-warnings
```

The local run log is `.task-v060-p3-pytest.log`. The test-output parent directory
must exist before running this command. An initial invocation stopped at fixture
setup because that directory was absent; it was created before the full rerun.

An independent in-process baseline comparison loaded the committed route source
and current route into separate namespaces without changing production files.
Injecting an HTTP 429 dependency exception into each read returned 429 from the
baseline and redacted 503 from the current handler, confirming the regression.
Ruff lint and formatting checks passed for both changed Python files.

Focused tests passed: **72 passed, 508 warnings in 1122.09 seconds**, exit 0,
using the selected interpreter and the two complete suites above.

Hostile review passed: inspected the complete diff after the successful test
run. Authentication still precedes framing and evidence access; permission
failures cannot fall through into the service. Both reads preserve strict
response revalidation and owner/candidate/item binding. Missing and foreign
readback remain indistinguishable, while unexpected dependency exceptions cannot
supply response bodies or headers. Structured service errors keep their existing
mapping. The patch adds no import, route, consumer, service construction or
mutation path; lineage, idempotency and fixed-false authority remain unchanged.
The regressions cover both handlers, successful-looking and redirect exceptions,
authentication-like exceptions, not-found and unavailable failures, redaction and
zero journal effects. `git diff --check` passed.

Full UI/build/release gates were not run for this API-only hardening. Historical
release obligations and deferred runtime-definition phases remain open.

## Commit storage limitation

The managed worktree's shared Git metadata is read-only: normal staging failed
when Git attempted to create its index lock. The implementation remains in the
managed worktree. A local bare clone at `.task-evidence/v060-p3/commit.git` stores
the task-owned commit, with its parent matching the original worktree HEAD and
its tree containing exactly these three reviewed file changes. The original
worktree branch pointer is unchanged; integration must import that commit.
