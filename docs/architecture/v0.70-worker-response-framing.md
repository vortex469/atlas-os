# v0.70 — complete worker responses within one deadline

Status: implementation and full affected suites passed; final committed-source
container integration is pending. Unreleased. Depends on v0.69; v0.71 onward
is outside the operator's selected completion target.

## Behavior and contract

The private worker client accepts one bounded HTTP/1.0 or HTTP/1.1 response,
with a single valid Content-Length. It rejects duplicate headers, conflicting
or chunked framing, malformed status/header lines, invalid lengths, premature
EOF and surplus bytes in the received frame. A complete frame returns without
waiting for server EOF. JSON must be a UTF-8 object without duplicate keys or
non-finite constants. Malformed error envelopes produce a controlled error
code instead of propagating arbitrary worker text or unhandled type errors.

A single monotonic deadline covers connect, send, response reads and decoding.
Every blocking operation uses its remaining time, so trickling bytes cannot
reset the timeout indefinitely. Invalid timeout values and CR/LF injection in
credentials or original-result identifiers are rejected before contact. The
v0.69 header/body byte budgets remain unchanged.

These refusals raise the existing WorkerTransportError. The backend retains
an unknown outcome, applies no patch and performs no execution retry or local
fallback. The operator can separately check the original request. No new
approval, effect API, model invocation or production authority is introduced.
The existing JSON worker response and immutable request wire schemas/hashes
are unchanged. Old peers without supported framing fail closed; no automatic
peer upgrade or rollout follows.

## Validation

The complete Agent suite passed **1,124 tests**, including malformed framing,
duplicate headers/JSON keys, invalid roots/numbers/UTF-8, fragmented reads,
maximum escaped result text, controlled error envelopes, and request-injection
refusal. A real loopback server sends bytes more frequently than the old
per-read timeout: the client still stops at its total deadline. Existing
candidate approvals, patch journals, persistence and no-replay recovery pass.

All **62 worker tests** pass. Maintained credential-free process probes pass
both on the host and in the updated hardened runsc image: simultaneous 2 MiB
streams retain only bounded prefixes, and timeout stops the inherited child.
Two real-TCP response-loss/restart tests also pass in that image with an inert
runner and the strict client, preserving one execution attempt. Image:
`sha256:151e3fbeb75e7e2f748ee631255baff4877016f6bc9b74916669f38e9513b61b`.

The configured Agent changed-file Ruff gate and focused worker Ruff checks
pass. The existing quality workflow now runs the worker regression suite and
maintained process probe alongside the Agent checks, without account credentials.
UI and Core implementation are unchanged; this milestone does not claim a new
UI/production acceptance run. Evidence is ignored under
`.task-evidence/v067-v070/`, not committed logs or model credentials.

## Limits and completion boundary

No real model invocation or account credential use was needed for v0.67–v0.70.
The earlier v0.66 shell-edit fixture and its separately approved terminal audit
remain historical proof; they are not a new model run on this source. Nested
patch-helper compatibility remains unresolved, Git patch generation is not
made memory-bounded by these scopes, and deliberately escaped process sessions
still require outer sandbox isolation. Future scopes remain unimplemented.

No production activation, release acceptance, remote exact-SHA CI, push, tag
or publication is authorized or claimed. The final container/recovery gate
result and exact implementation commit will be recorded after that run.
