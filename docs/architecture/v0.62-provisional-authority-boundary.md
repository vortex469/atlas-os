## Evidence required before selection

All gates below remain open for a successor; this P0 does not claim feasibility.

1. **Accepted baseline:** pin the final integration commit, actual pair and
   predecessor acceptance evidence. Resolve the open v0.61 and inherited release
   obligations explicitly. A focused P0 pass or the recorded UI pass cannot close
   them. Re-analyze if the predecessor changes; never fall back to an older stage.
2. **Distinct predicate and trusted provenance:** demonstrate two declarations
   over the same exact inventory input, one consistent and one with a capability
   that conflicts with a lifecycle constraint. Identify the trusted author and
   deterministic source of that constraint and the concrete consumer decision
   affected. Specify refusal versus a closed negative finding, without silent
   repair. These are conceptual cases, not schema literals. If v0.55 design,
   v0.56 review or v0.57 checks already distinguish them, retain documentation.
3. **Exact owned stable pins:** separately approve a reader binding authenticated
   `operator_id`, `candidate_record_id`, exact `runtime_interface_prerequisite_id`,
   record fingerprint, stable status fingerprint and inherited expiry. Derive
   stable status at inventory `recorded_at`, and independently check current
   eligibility at trusted whole-second UTC Core time. Reject foreign ownership,
   substituted hashes, caller-supplied nested evidence, latest/worker lookup and
   expired lineage. Current item status and unpaired list entries cannot substitute.
4. **Recursive integrity and measured bounds:** preserve complete immutable
   lineage, all six stage/predecessor IDs, version-specific hashes, subjects and
   historical times. Reparse copy/construct bypasses; reject extras, duplicate
   fields and coercion. Measure expanded full record, status, result and collection
   bytes and evaluation duration for the exact proposed embedding, including
   overflow refusal. Retain 192 KiB per full model/response, 30-second freshness,
   16 reservations per owner, 256 global and 256 MiB main SQLite pages (not a
   filesystem quota). No lineage truncation, limit increase or expiry renewal.
5. **Durability and uncertainty:** select exact domains/vectors and permanent
   owner/candidate/exact-predecessor subject only after normative selection.
   Subject identity excludes key, content and expiry. Require separate default-off
   explicit construction, locked revalidation, reservation before append, terminal
   uncertainty and restart no-replay without predecessor journal mutation.
6. **No authority promotion:** test consistent declarations with missing runtime
   or contact proof, forged lineage, foreign/stale statuses, true and false invented
   fields and forbidden payload material. Both declaration examples leave all
   operational blockers unresolved; recording cannot create readiness.

Failure to prove any gate leaves successor P1-P5 deferred. Release acceptance
